# 阶段 1：需求澄清与 MVP 范围
> 项目：AI 营销视频智能体（代号 **MVA / Marketing Video Agent**）
> 状态：待确认（确认后进入阶段 2 总体架构）

---

## 0. 一句话定义

一个 **「一句需求 → 可发布营销短视频」的智能体**，同时提供 **LibTV 式无限画布节点工作流**：
用户既能手动搭流程，也能让 Agent 自动在画布上生成/修改流程，二者操作**同一份工作流数据模型**。

## 1. 假设清单（不成立时的影响已标注）

| # | 假设 | 若不成立的影响 |

| A7 | 素材上传即由用户声明版权/肖像授权（勾选 + 留痕），**不做自动鉴权** | 需引入第三方 IP 库与人工审核岗 |
| A8 | MVP **单租户**，但 DB 预留 `tenant_id` / `workspace_id` | 企业定制需数据迁移 |
| A9 | 自动质检覆盖：技术质量 + 合规 + 文案一致性；镜头一致性用 CLIP/VLM 相似度打分，**人工可覆盖** | 若要求全自动零人工，需更高阈值模型与更多评测数据 |
| A10 | `WorkflowGraph` JSON 是**唯一真相源**，Agent 只能通过 Patch 修改 | 双真相源 → 手动与 Agent 编排必然互相覆盖 |
| A11 | MVP 用 Docker Compose 单机部署（K8s 留阶段 9） | 高并发上线需提前容器化改造 |
| A12 | 前端定：**React 19 + TS + React Flow 12 + Zustand + Tailwind + shadcn/ui + Vite**（不选 Vue） | 若团队为 Vue 栈，则换 VueFlow，节点协议不变 |

## 2. 用户旅程（3 条主旅程）

### J1 一句话成片（Agent-first，新手，目标 < 5min 出片）
1. 新建项目 → 填「营销目标 / 产品 / 平台 / 时长 / 风格」+ 拖入素材（图/视频/文字）。
2. 用户说一句：*"给这款气泡水做一条 20s 抖音种草视频，清爽夏日感，突出 0 糖"*。
3. Agent 澄清（≤2 轮，缺关键信息才问）：卖点、目标人群、是否有真人出镜授权。
4. Agent 在画布上**生成一张工作流图**（脚本 → 分镜 → 图像 → 视频 → TTS → 校验 → 合成），以**提案卡片**呈现。
5. 用户点「接受并运行」→ 画布实时显示节点状态与进度，中途可展开任意节点改参数后**单节点重跑**。
6. 质检节点给出报告；用户选定终稿 → 导出 MP4 + 封面 + 文案 + 成本账单。

### J2 手动编排（Canvas-first，熟练运营）
1. 从左侧模板库拖入「产品图生视频」模板 → 画布实例化。
2. 双击空白处新建节点，拖拽连线，改提示词、调分辨率/比例/数量。
3. 选中一组节点 → `Cmd+G` 打组 → 存为模板（命名 + 版本 v1）。
4. 全量运行 / 选子图运行；失败节点单独重试；上游改动后下游自动标记 `stale`。

### J3 模板复用与企业定制（企业客户）
1. 代理商在模板库维护「品牌模板」：固定 logo、片头片尾、语调、禁用词、模型白名单、预算上限。
2. 客户只填变量（产品名、卖点、素材）→ 一键出片，风格恒定。
3. 模板版本升级，历史工作流仍绑定旧版本可复现（`template_id + template_version`）。

## 4. 关键设计决策：画布手动编排 ↔ Agent 自动编排的关系

### 4.1 单一真相源（Single Source of Truth）
两种模式**不是两个产品**，而是同一份 `WorkflowGraph` 的三个入口：

```
                   ┌──────────────────────────┐
   画布手动编辑 ──▶ │                          │
   Agent 对话   ──▶ │   WorkflowGraph (JSON)   │ ──▶ 执行引擎 (拓扑调度)
   模板实例化   ──▶ │  = 可序列化 / 可版本化   │ ──▶ 持久化 + 模板导出
                   └──────────────────────────┘
```

- 画布是 **DSL 的可视化编辑器**；Agent 是 **DSL 的生成器/修改器**。
- 任何一方产生的变更都落成同构的 `GraphPatch`（操作序列），进统一 undo 栈。

### 4.2 Agent 不改整图，只提交 Patch
```jsonc
// Agent 输出（结构化）
{
  "patch_id": "p_01H...",
  "base_version": 12,              // 乐观锁：基于哪个版本改的
  "rationale": "用户要求突出 0 糖，补充产品特写镜头",
  "ops": [
    {"op": "add_node", "node": {"id": "n_7", "type": "image", "params": {...}}},
    {"op": "update_node_params", "node_id": "n_3", "params": {"prompt": "..."}},
    {"op": "connect", "edge": {"source": "n_3", "source_port": "image", "target": "n_7", "target_port": "image"}},
    {"op": "move", "node_id": "n_7", "position": {"x": 640, "y": 320}}
  ]
}
```
**收益**：可撤销、可审计、可回放、可与用户并发编辑合并（而不是整图覆盖）。

### 4.3 冲突与协同规则
| 规则 | 说明 |
|---|---|
| 乐观锁 | `patch.base_version != graph.version` → 走三方合并（base / user / agent） |
| 字段级合并 | 不同节点或不同字段的变更自动合并 |
| 节点级冲突 | 同节点同字段冲突 → **保留用户值**，Agent 变更降级进「提案箱」 |
| 锁定 | `node.locked = true`（用户右键锁定）→ Agent 禁止修改/删除该节点，违反则拒绝该 op |
| 提案制 | 高风险操作（删节点 > 2 个、改模板结构、成本预估 > 阈值）→ 强制「提案卡片」，用户 Accept / Reject / 部分接受 |
| 撤销 | `Cmd/Ctrl+Z` 可撤销 Agent 的任意一次 Patch（含整批） |
| 可追溯 | 每个节点/边记录 `created_by: "user" \| "agent" \| "template"` 与 `updated_at` |

### 4.4 权限矩阵
| 能力 | 用户 | Agent |
|---|---|---|
| 读图 | ✅ | ✅ |
| 改节点参数 | ✅ | ✅（locked 除外） |
| 增/删节点、改拓扑 | ✅ | ✅（超阈值转提案） |
| 触发运行 | ✅ | ✅（受预算与审核闸门） |
| 锁定 / 解锁 | ✅ | ❌ |
| 删除工作流 / 发布模板 | ✅ | ❌ |
| 覆盖用户手改值 | ✅ | ❌（冲突时用户优先） |

### 4.5 状态机（两套，互不混淆）
**工作流级**：`draft → ready → running → (succeeded | failed | partial) → exported`（`exported` 后仅可另存为新版本）

**节点级**：`idle → queued → running → (success | failed | skipped | cancelled)`；上游产物变更后置为 **`stale`**（黄色边框，提示可重跑）。

## 5. MVP 范围

### 5.1 In（P0，4 周 / 2 人前端 2 人后端）
- **画布**：无限画布、缩放平移、拖拽、框选多选、对齐吸附、连线、撤销重做、双击建节点、外部文件拖入、`Cmd+G` 打组、模板库左侧栏。
- **节点（8 类，注册表驱动可扩展）**：文本 / 图像 / 视频 / 音频 / 脚本 / 提示词编译 / 质检 / 合成。前三类含内联预览（缩略图、播放器、波形）。
- **执行**：单节点 / 子图 / 全量；拓扑排序 + 并行分支；状态色 + 日志面板（输入输出/耗时/模型/成本）。
- **Agent**：澄清 → Brief → 生成工作流 Patch → 提案 UI；脚本/文案/提示词编译 3 个 Skill 可版本管理。
- **流水线**：文案 → 分镜 → 素材匹配 → Prompt 编译 → 图像 → 视频 → TTS → 校验 → 合成导出 MP4。
- **适配器**：`ImageModel` / `VideoModel` / `TTSModel` / `LLMModel` 统一接口 + 注册表 + 假实现（Mock）用于离线联调。
- **工程**：FastAPI + Pydantic、Postgres、Redis + Arq 队列、MinIO、FFmpeg、WebSocket 状态推送、结构化日志 + 每节点成本账。
- **三条闸门**：内容审核（三层）、版权/肖像留痕 + AI 生成标识、成本上限熔断。

### 5.2 Out（MVP 不做，路线图登记）
企微/发布对接、数字人、实时直播、时间线精细非编、多人协作 CRDT、K8s 多租户计费、LoRA 训练、素材自动版权鉴权、移动 App。

### 5.3 里程碑
| 周 | 交付 |
|---|---|
| W1 | 数据模型 + DSL + 画布骨架（节点 CRUD/连线/撤销）+ Mock 执行引擎跑通「文本→图像」 |
| W2 | 后端工作流 CRUD + 队列 + 适配器（接 1 文生图 + 1 LLM）+ WebSocket 状态 |
| W3 | 全流水线（脚本/分镜/编译/视频/TTS/合成/质检）+ 成本账 + 审核闸门 |
| W4 | Agent Patch 生成 + 提案 UI + 模板保存/导入导出 + E2E 评测 + 单机部署 |

## 6. 非目标（明确不做，防止范围蔓延）
1. 不做自研基础模型/训练。
2. 不做平台账号托管与自动发布（合规风险高，二期评估）。
3. 不做实时直播、数字人直播。
4. 不做专业级非线性编辑（多轨时间线、关键帧曲线）。
5. 不做多人实时协同编辑（MVP 单人单工作流）。
6. 不做计费/订阅系统（仅成本账与预算上限）。
7. 不做 4K/长视频（>3min）优化。

## 7. 硬约束的 MVP 最小实现

### 7.1 内容审核（三层闸门，任一命中即阻断）
```
L1 输入素材审核 → L2 Prompt/文案审核 → L3 输出成片审核（抽帧 + ASR 文本）
命中 → 节点状态 failed(reason=policy_blocked) + audit_log 记录 + 用户可见原因
```
- 机审：文本敏感词/模型安全接口 + 图像/视频抽帧安全接口；阈值可配。
- 留痕：`audit_log(workflow_id, node_id, stage, verdict, categories[], model, raw, created_at)`。
- 申诉：MVP 只做「人工复核放行」开关（管理员角色）。

### 7.2 版权 / 肖像风险
- 上传即弹「授权声明」勾选，落 `consent_record(asset_id, subject_type=真人|品牌|第三方, license_scope, expires_at, evidence_ref)`。
- 真人素材打 `portrait=true` 标签；Agent 在未授权场景**禁止**选用（编译期硬校验）。
- 输出成片写入 **AI 生成标识**（元数据 + 平台合规声明文案 + 可选可见水印）。

### 7.3 成本上限
- `workflow.budget_limit_cny`（默认 8）；每个节点有 `estimated_cost`。
- 执行前预检：`Σ本子图预估 + 已花费 > limit` → 暂停并弹出「继续/调整/取消」。
- 每次模型调用写 `cost_ledger(workflow_id, node_id, adapter, model, unit, qty, cost_cny, latency_ms)`；节点面板实时显示本次花费。

## 8. MVP 验收标准（DoD，可测）

1. 新用户 5 分钟内完成 J1 全流程并导出 1 条 ≥15s 竖屏 MP4。
2. 画布：200 节点 / 300 边下缩放平移 ≥50fps；撤销 ≥50 步；导出 JSON → 新会话导入 → 图完全一致。
3. 执行：单节点失败不影响无关分支；重试 3 次幂等（不产生重复产物）；`stale` 标记正确传播。
4. Agent：一句话生成的图可通过 DSL 校验；不修改 `locked` 节点；`Cmd+Z` 可撤销整个 Patch。
5. 审核：构造违规 prompt 与违规素材各 1 例，均被阻断且有 audit_log。
6. 成本：预算设为 ¥1 时全量运行被熔断并提示，实际花费 ≤ ¥1。
7. 新增第 9 种节点类型：仅新增组件 + Schema 注册，画布核心文件**零改动**（回归测试通过）。
8. 评测集：20 条样例，自动出「一致性/画质/合规/成本/时延」5 项指标报告。
9. 可观测：每个节点有 trace_id，能查 input/output/耗时/模型/成本。
10. 断点续跑：中途 kill worker，重启后任务从失败节点续跑（已完成节点不重跑）。
